# Quadcopter CAD

مدل مرجع این مخزن، نسخهٔ پارامتریک **smooth2** است. هندسه فقط از سازندهٔ اصلی و دادهٔ مقاطع آن تولید می‌شود.

## ساختار پروژه

```text
.
├── .github/workflows/
│   └── regenerate-smooth2-parametric.yml
├── cad/parametric/
│   ├── drone_parametric.py
│   └── body_sections.json
├── output/
│   └── smooth2-parametric/
│       ├── README.md
│       ├── drone_parametric.step
│       ├── drone_parametric.stl
│       ├── drone_parametric_assembled.stl
│       ├── drone_parametric_exploded.stl
│       ├── drone_parametric.params.json
│       ├── assembly-manifest.json
│       ├── validation-report.json
│       └── فایل‌های مستقل STEP و STL قطعات
└── README.md
```

## مرجع هندسه

| کاربرد | فایل |
|---|---|
| سازندهٔ اصلی و تنها منبع تولید هندسه | `cad/parametric/drone_parametric.py` |
| دادهٔ مقاطع بدنه و تاج | `cad/parametric/body_sections.json` |
| خروجی‌های قابل استفاده و گزارش‌ها | `output/smooth2-parametric/` |
| مستندات فنی مدل | `output/smooth2-parametric/README.md` |
| ساخت و کنترل خودکار | `.github/workflows/regenerate-smooth2-parametric.yml` |

فایل‌های خروجی، محصول اجرای سازنده هستند و منبع مستقل طراحی محسوب نمی‌شوند. تغییر هندسه باید در سازنده یا دادهٔ مقاطع انجام شود؛ سپس خروجی‌ها دوباره تولید شوند.

## راه‌اندازی و تولید خروجی

با Python 3.11 یا محیط سازگار:

```bash
python -m pip install --upgrade pip
python -m pip install cadquery numpy trimesh
python cad/parametric/drone_parametric.py
```

برای استفاده از snapshot پارامترهای دیگر:

```bash
python cad/parametric/drone_parametric.py --params path/to/params.json
```

خروجی‌ها در `output/smooth2-parametric/` نوشته می‌شوند. اجرای سازنده فایل‌های اسمبلی و قطعات مستقل STEP/STL، snapshot پارامترها، مانیفست و گزارش اعتبارسنجی را به‌روزرسانی می‌کند.

## مشخصات مدل مرجع

مقادیر زیر از سازنده و گزارش اعتبارسنجی فعلی استخراج شده‌اند:

- مقیاس یکنواخت: `1.414028`
- ابعاد کلی اسمبلی: حدود `271.890 × 271.856 × 49.938 mm`
- تعداد اجزای اسمبلی: ۲۶ جسم مستقل
- بازوی اصلی: حدود `22.624 × 16.968 mm` در مقطع
- ریشهٔ بازو: اتصال دوشاخهٔ تیک‌شکل با زاویهٔ داخلی ۱۱۰ درجه
- طول شاخه‌های ریشه در فضای پارامتریک: ۲۲ و ۱۴ واحد
- عرض شاخه‌ها: ۶۰٪ عرض بازوی اصلی
- ضخامت اسمی کف و پوسته: حدود `2.828 mm`
- قطر پروانه: حدود `74.802 mm`
- لقی شعاعی محاسباتی پروانه تا محافظ: حدود `4.596 mm`

جزئیات ابعادی، جهت‌ها، اتصال بازوها، فهرست قطعات و محدودیت‌های طراحی در مستند فنی پوشهٔ خروجی آمده است. گزارش JSON تولیدشده، مرجع مقادیر حاصل از آخرین اجرا است.

## اجزای اسمبلی و فایل‌ها

مدل شامل پوستهٔ پایینی، تاج، چهار مجموعهٔ بازو، چهار پروانه، هشت پیچ و هشت مهره است. برای هر جزء، فایل STEP و STL جداگانه تولید می‌شود. فایل STEP اسمبلی، ساختار ۲۶ جزئی را نگه می‌دارد. فایل‌های STL اسمبلی و چیدمان انفجاری برای مشاهده و گردش‌کارهای مش ارائه می‌شوند.

## کنترل کیفیت خودکار

Workflow اختصاصی این پروژه با تغییر سازنده، دادهٔ مقاطع یا خود workflow و نیز با اجرای دستی روی شاخهٔ کاری اجرا می‌شود. کنترل‌ها شامل موارد زیر هستند:

1. نصب وابستگی‌های CAD؛
2. اجرای سازنده از منبع واحد؛
3. کنترل کامل‌بودن خروجی‌ها و مانیفست ۲۶ جزئی؛
4. کنترل هندسهٔ کف، اتصال پیچ‌ها و ریشه‌های بازو؛
5. بررسی لقی پروانه و محافظ؛
6. بررسی watertight بودن تمام فایل‌های STL؛
7. واردسازی مجدد تمام فایل‌های STEP و کنترل تعداد solidها؛
8. انتشار خروجی‌های تأییدشده فقط در شاخهٔ کاری.

اگر هر آزمون شکست بخورد، انتشار خروجی انجام نمی‌شود. تغییر فایل‌های خروجی به‌تنهایی باعث اجرای مجدد workflow نخواهد شد.

## محدودیت‌ها

- هندسه یک بازسازی پارامتریک بر اساس اندازه‌گیری‌های مرجع است و تاریخچهٔ featureهای CAD اولیه را بازسازی نمی‌کند.
- پیچ و مهره‌های مدل، حجم‌های ساده‌شده و بدون رزوه هستند؛ سخت‌افزار واقعی باید جداگانه انتخاب شود.
- سوراخ و انطباق نهایی شفت موتور در توپی پروانه هنوز باید با موتور انتخابی تطبیق داده شود.
- روش اتصال نهایی تاج به پوستهٔ پایینی در مدل تعریف نشده است.
- قبولی آزمون‌های نرم‌افزاری، تأیید چاپ‌پذیری، استحکام، بالانس، تحمل دور موتور یا ایمنی پرواز نیست. پیش از استفاده، چاپ آزمایشی و آزمون مکانیکی لازم است.

## قواعد نگهداری

- فقط سازنده و دادهٔ مستقیم موردنیاز آن، منبع هندسه هستند.
- فایل‌های تولیدشده را دستی ویرایش نکنید؛ آن‌ها را با اجرای سازنده بازتولید کنید.
- وابستگی جدید فقط در صورت استفادهٔ مستقیم و مستند در فرایند ساخت یا اعتبارسنجی اضافه شود.
- تغییرات مدل و خروجی‌های متناظر باید در یک اجرای موفق کنترل کیفیت بررسی شوند.
