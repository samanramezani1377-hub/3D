# Quadcopter CAD — smooth2

این مخزن یک مدل مرجع دارد: **smooth2-parametric**. تمام فایل‌های هندسی قابل استفاده باید از یک منبع پارامتر و یک سازنده تولید شوند.

## منبع واحد حقیقت

| لایه | مسیر | نقش |
|---|---|---|
| هندسه‌ساز | `cad/parametric/drone_parametric.py` | تنها کد مجاز برای ساخت هندسه و خروجی‌ها |
| پارامترهای مدل | `cad/parametric/model.params.json` | تنها مرجع ابعاد و تنظیمات مدل |
| مقاطع اندازه‌گیری‌شده | `cad/parametric/body_sections.json` | دادهٔ هندسی مستقیم موردنیاز سازنده |
| وابستگی‌های قفل‌شده | `requirements.txt` | نسخه‌های دقیق محیط تولید |
| خروجی‌ها | `output/smooth2-parametric/` | فایل‌های تولیدشده و گزارش‌های همان اجرا |
| کنترل خودکار | `.github/workflows/regenerate-smooth2-parametric.yml` | تولید، تطبیق و انتشار خروجی معتبر |

هیچ نسخهٔ پارامتر جداگانه یا تنظیمات پیش‌فرض تکراری در کد وجود ندارد. سازنده مستقیماً `model.params.json` را می‌خواند؛ اجرای ساخت با پارامتر ناقص یا override قدیمی پشتیبانی نمی‌شود. فایل `drone_parametric.params.json` در پوشهٔ خروجی فقط snapshot بایت‌به‌بایت از فایل مرجع است، نه منبع تنظیمات دوم.

## تولید مجدد

از ریشهٔ مخزن، در Python 3.11:

```bash
python -m pip install -r requirements.txt
python cad/parametric/drone_parametric.py
```

برای تغییر مدل، فقط `cad/parametric/model.params.json` یا `cad/parametric/body_sections.json` را ویرایش کنید. برای تغییر منطق ساخت یا کنترل، سازنده را ویرایش کنید. سپس کل بسته را دوباره بسازید؛ فایل‌های STEP/STL را دستی اصلاح نکنید.

## قواعد یکسانی خروجی‌ها

- اسمبلی STEP و STL مونتاژشده از دقیقاً همان ۲۶ جسم CadQuery و همان مختصات ساخته می‌شوند.
- `drone_parametric.stl` یک کپی بایت‌به‌بایت از `drone_parametric_assembled.stl` است؛ نام پیش‌فرض STL دیگر به چیدمان انفجاری اشاره نمی‌کند.
- فایل‌های STEP و STL مستقل هر جزء از همان جسم پارامتریک ساخته می‌شوند.
- `drone_parametric_exploded.stl` فقط چیدمان نمایشی انفجاری است؛ قطعات آن از همان هندسهٔ اجزا استفاده می‌کنند و صرفاً برای نمایش جابه‌جا شده‌اند.
- خروجی‌های اسمبلی و قطعات، با محور Z رو به بالا و قرارداد جهت یکسان صادر می‌شوند.
- گزارش، هش SHA-256 سازنده، پارامترها و دادهٔ مقاطع را ثبت می‌کند؛ snapshot پارامترها باید دقیقاً با فایل مرجع برابر باشد.
- گزارش، ۲۹ فایل STL را از نظر watertight بودن، ۲۷ فایل STEP را با import مجدد، و جفت‌های STEP/STL را از نظر ابعاد bounding box کنترل می‌کند.
- CI هش فایل‌های خروجی STEP/STL را نیز ثبت و تطابق تنظیمات و خروجی‌ها را کنترل می‌کند.

## کنترل کیفیت

Workflow شاخهٔ `kilo` با تغییر هر یک از ورودی‌های اصلی یا با اجرای دستی فعال می‌شود. نسخهٔ Python و تمام وابستگی‌ها در `requirements.txt` قفل شده‌اند. اگر فایل ناقص باشد، پارامترها با snapshot برابر نباشند، هش ورودی‌ها تغییر کرده باشد، تعداد اجزا نادرست باشد، یا آزمون STEP/STL شکست بخورد، خروجی منتشر نمی‌شود.

## مشخصات و محدودیت‌های طراحی

مدل فعلی شامل ۲۶ جزء است: پوستهٔ پایینی، تاج، چهار مجموعهٔ بازو/محافظ/موتور، چهار پروانه، هشت پیچ نمایشی و هشت مهرهٔ نمایشی. اتصال بازوها با ریشهٔ دوشاخهٔ تیک‌شکل و پیچ‌های عمودی از زیر بدنه طراحی شده است.

مدل یک بازسازی پارامتریک از اندازه‌گیری‌های مرجع است، نه تاریخچهٔ featureهای CAD اولیه. پیچ و مهره‌ها حجم‌های ساده‌شده و بدون رزوه‌اند؛ سوراخ اتصال شفت پروانه باید با موتور واقعی تطبیق داده شود؛ روش اتصال تاج به بدنه هنوز نهایی نشده است. قبولی آزمون نرم‌افزاری به معنی تأیید تلرانس چاپ، استحکام، بالانس، تحمل دور موتور یا ایمنی پرواز نیست. پیش از استفاده، چاپ آزمایشی و آزمون مکانیکی لازم است.
